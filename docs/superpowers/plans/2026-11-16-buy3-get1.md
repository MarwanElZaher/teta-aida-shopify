# Buy 3, the 4th is on us — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Show Shopify's automatic "buy 3 jars, cheapest 4th free" discount everywhere on teta3ayda.com (ribbon, badges, product note, cart progress, gift picker, free-line tag, summary line) without the site ever computing prices itself.

**Architecture:** Shopify admin owns the rule and the price. One pure module `app/lib/offers.ts` holds the offer config and all offer math (active window, eligibility, progress, free units, savings); React components only render its results. Eligibility comes from the product's collections (`pickles-products`), the free line from the cart line's automatic discount allocation title.

**Tech Stack:** Hydrogen 2025.7.0, React Router 7, React 18.3.1, Vite 6, Tailwind, Storefront API codegen; Vitest (added in Task 1) for the pure module.

**Spec:** `docs/superpowers/specs/2026-11-16-buy3-get1-design.md`

## Global Constraints

- Repo `teta-aida-shopify`, branch `feat/buy3-get1`. Push to `main` deploys production (teta3ayda.com); never push `main` until Task 7.
- The site never computes a price. Totals and the free jar come only from the Shopify cart response.
- Collection handle `pickles-products`; buy 3, get 1; boxes/bundles never count.
- Admin discount title, exactly: `اشتري ٣ والرابع علينا` (same string in `OFFER.discountTitle`).
- `OFFER.enabled` stays `false` in every commit until the automatic discount is live in Shopify (Task 7).
- Every user-facing string exists in both `TRANSLATIONS.EN` and `TRANSLATIONS.AR` in `app/lib/translations.ts`; Arabic copy is gender-neutral.
- Do not touch `app/lib/cartDiscounts.ts` or the DiscountCodesUpdate case in `app/routes/($locale).cart.tsx` (Hydrogen 2025.7 mutation workaround).
- Typecheck baseline is 29 pre-existing errors; a task may not add new ones (`npm run typecheck 2>&1 | grep -c "error TS"` ≤ 29).
- `npm run build` must pass after every task (it also runs codegen).
- Shopify CLI dev server needs a device login and the preview sandbox can't read `.env`; verify UI with `npm run build` + `npm run preview` only if it works, otherwise with the live checks in Task 7. Follow `~/.claude/bin/sandbox-status` before starting any server.

## Review Focus

1. **Title mismatch** (owner edits the discount title, or Shopify returns a different title on /ar) → the free tag and offer line silently vanish but totals stay correct via the generic "Discount" line. Pinned by `freeUnits ignores allocations with another title` (Task 2) and the both-locales tag check (Task 7).
2. **Partly free line** (2 turnips + 2 olives: one turnip free, one paid on the same line) → tag reads "هدية ×١", not a whole free line. Pinned by `marks one unit free on a two-unit line` (Task 2).
3. **Optimistic and bundle lines** (lines added client-side by `useOptimisticCart` have no `product.collections`; bundle lines are `ComponentizableCartLine`) → counted as 0, never crash. Pinned by `lines without collections do not count` (Task 2).
4. **Offer window edges** (Cairo time, start/end instants) → no UI outside the window. Pinned by `isOfferActive boundaries` (Task 1).
5. **Max free jars reached** (`maxPerOrder` set and earned) → no further nudge and no gift picker. Pinned by `stops nudging at maxPerOrder` (Task 1).

  ```ts
    maxPerOrder: number | null; discountTitle: string;

  export function isOfferProduct(config: OfferConfig, collectionHandles: readonly string[]): boolean;
  export type OfferProgress = {
    state: 'none' | 'progress' | 'unlocked';
    needed: number;   // jars still to add for the next free one (0 when unlocked/maxed)
    earned: number;   // free jars earned, capped at maxPerOrder
    showGiftPicker: boolean; // state==='progress' && needed===1
  };
  export function getOfferProgress(config: OfferConfig, eligibleQty: number): OfferProgress;
  ```

Progress rule (group = buyQty + getQty = 4): `q = 0` → `none`. `earned = min(floor(q/4), maxPerOrder ?? ∞)`. If `maxPerOrder` reached → `unlocked`, `needed 0`. Else if `q % 4 === 0` → `unlocked`, `needed 0`. Else `progress`, `needed = 4 − q % 4`.
